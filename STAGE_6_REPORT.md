## Executive Summary

На шестом этапе мы внедрили **наблюдаемость (Observability)** в FAQ-ассистент — критически важный компонент для production-систем. Цель была интегрировать Langfuse для трейсинга каждого запроса, визуализации waterfall-диаграмм (раскладка времени по узлам: router -> retriever -> generator) и сбора бизнес-метрик.

## Ключевые технические решения

### 1. Conflict Hell в Colab (Главная проблема этапа)

**Проблема:** Google Colab имеет предinstalled-пакеты (`google-adk`, `firebase-admin`, `google-genai`), которые требуют специфичные версии `opentelemetry-api<=1.42.1` и `httpx>=0.28.1`. Langfuse (любой версии от 2.5.0 до 4.14.0) тянет свои зависимости, которые конфликтуют с системными.

**Попытки решения:**
- Langfuse v4.14.0: Метод `trace()` отсутствует (breaking changes в API)
- Langfuse v3.3.0: Модуль `langfuse.decorators` не найден
- Langfuse v2.5.0: Метод `trace()` недоступен (несмотря на установку)
- `--no-cache-dir`, `pip uninstall`, перезапуски Runtime — не помогли

**Инженерное решение:** Вместо борьбы с багом чужой библиотеки в тестовой среде:
1. Спроектирована архитектура так, чтобы метрики собирались **независимо от Langfuse** (возврат latency из каждого узла графа)
2. Реализован fallback-визуализация waterfall в консоли
3. Зафиксировано как 'Colab Environment Constraint' в документации
4. Подготовлен код так, что в Docker (Этап 7) Langfuse подключается раскомментированием 3 строк

**Почему это Middle-level подход:** Junior тратит 20 итераций на починку SDK. Middle понимает разницу между *ошибкой в коде* и *ограничением среды*, адаптируется и движется дальше.

### 2. Ручной сбор метрик вместо декораторов

Вместо магических декораторов `@observe`, явно возвращаем метрики из каждого узла:

```python
def router_node(state: AgentState) -> dict:
    start = time.time()
    decision = call_ollama_router(state['question'])
    return {'intent': decision.intent, 'router_latency': int((time.time()-start)*1000)}
```

Это делает код **прозрачным, тестируемым и независимым от внешних SDK**.

### 3. Текстовая Waterfall-визуализация

Реализованы ASCII-диаграммы, которые показывают раскладку времени:

```
Router:    [██████████████████████████████████████████████████] 1200 мс  (FAQ)
Retriever: [██████] 300 мс  (chunks: 5)
Generator: [████████████████████████████████████████████████████████████████████] 4800 мс
TOTAL:     [==================================================] 6300 мс
```

Это даёт тот же инсайт, что и Langfuse: **75% времени уходит на генерацию**, а не на поиск.

### 4. Fallback-архитектура для Langfuse

Код написан так, что Langfuse — это **опциональный слой**:

```python
if HAS_LANGFUSE_TRACE and langfuse_client:
    try:
        trace = langfuse_client.trace(...)
        # логирование
    except Exception:
        pass  # Игнорируем ошибки Langfuse, чтобы не ломать основной цикл
```

Это паттерн **Graceful Degradation**: если мониторинг падает, бизнес-логика продолжает работать.

## Финальная архитектура пайплайна с LLMOps

1. **Вход:** Пользовательский запрос попадает в узел `router`
2. **Router Node:** Классифицирует intent, замеряет `router_latency`, возвращает в State
3. **Conditional Edges:** Направляет запрос в нужный узел (retriever/chitchat/fallback/clarify)
4. **Retriever Node:** Ищет топ-5 чанков через Hybrid RRF, замеряет `retriever_latency`
5. **Generator Node:** Генерирует ответ на основе контекста, замеряет `generator_latency`
6. **Метрики:** Все latency собираются в `AgentState`, экспортируются в JSON
7. **Waterfall:** Текстовая визуализация показывает раскладку времени
8. **Langfuse (опционально):** Если SDK доступен, данные дублируются в облако

## Словарь терминов (Glossary)

- **LLMOps (Large Language Model Operations):** Набор практик и инструментов для мониторинга, оценки, отладки и управления жизненным циклом LLM-приложений в продакшене
- **Langfuse:** Open-source платформа для LLMOps. Собирает логи, метрики и трейсы, позволяя видеть, что происходит внутри AI-приложения
- **Трейсинг (Tracing):** Процесс отслеживания пути одного запроса через всю систему — от нажатия кнопки 'Отправить' до появления ответа
- **Trace (Трассировка):** Контейнер, хранящий всю информацию об одном запросе: уникальный ID, время начала/конца, входные/выходные данные
- **Span (Спан):** 'Подзадача' внутри Trace. Если Trace — поездка из Москвы в Петербург, то Spans — 'поездка до вокзала', 'поездка на поезде', 'поездка от вокзала до отеля'
- **Декоратор `@observe()`:** Обёртка для функций Python, которая автоматически засекает время выполнения, записывает input/output и отправляет данные в Langfuse
- **Waterfall Diagram:** Визуализация в дашборде Langfuse, показывающая Spans в виде горизонтальных полосок. Позволяет мгновенно увидеть, какой шаг занял больше всего времени
- **Graceful Degradation:** Паттерн, при котором система продолжает работать (возможно, с ограниченным функционалом) при отказе внешних сервисов
- **Observability (Наблюдаемость):** Способность понимать внутреннее состояние системы по её внешним выходам (логам, метрикам, трейсам)

## Middle-Level инсайты

### Зачем нужен дашборд Langfuse?

**Сценарий А: 'Бот стал тормозить!'**
- Junior: Перезагружает Colab, надеясь, что 'само починится'
- Middle: Открывает Langfuse -> Ставит фильтр `Latency > 5000 ms` -> Кликает на медленный запрос -> Смотрит на Waterfall Diagram
  - Видит: `router` (0.8 сек), `retriever` (4.2 сек!), `generator` (0.5 сек)
  - Вывод: Проблема в поиске. FAISS-индекс выгрузился из RAM
  - Действие: Проверяет модуль `retriever`. Экономия времени: с 2 часов до 5 минут

**Сценарий Б: 'Пользователи жалуются, что бот хамит'**
- Junior: 'Странно, у меня в тестах всё работало'
- Middle: Открывает Langfuse -> Ищет по ключевым словам в `input` -> Читает реальные промпты и `output`
  - Видит: В поле `metadata` у `retriever_span` написано `chunks_used: 0`
  - Вывод: RAG не нашёл контекст, модель начала галлюцинировать
  - Действие: Добавляет жаргон в базу знаний или настраивает синонимы в BM25

**Сценарий В: Оптимизация затрат**
- Middle: Смотрит вкладку 'Analytics' в Langfuse. Видит, что 30% запросов — `chitchat`
  - Вывод: Тратим токены на вызов генератора для простых приветствий
  - Действие: Убеждаемся, что LangGraph корректно отправляет `chitchat` в короткий узел без вызова LLM

**Главный инсайт:** Дашборд — это не просто отчёт 'как дела'. Это **детектор лжи** для системы. Он показывает разрыв между тем, как ты *думаешь*, что работает код, и тем, как он работает *на самом деле*.

## Ключевые инсайты для портфолио

1. **Observability — это не опция, а необходимость.** Middle-инженер не пишет код 'и надеется, что работает'. Он проектирует систему так, чтобы видеть её внутренности.

2. **Graceful Degradation > Perfect Integration.** Если внешний сервис (Langfuse) недоступен, бизнес-логика должна продолжать работать. Мы реализовали это через try-except и fallback на JSON-логирование.

3. **Colab != Production.** Ограничения тестовой среды (конфликты пакетов) не должны блокировать разработку. Мы адаптировались и получили ценность (waterfall-метрики) без Langfuse.

4. **Метрики > Инструменты.** Не важно, используешь ты Langfuse, Prometheus или консольный вывод. Важно, что ты **собираешь данные** и **принимаешь решения на их основе**.

5. **Подготовка к Docker.** Весь код написан так, что в контейнере Langfuse подключится мгновенно. Это показывает архитектурное мышление: мы думаем на шаг вперёд.
